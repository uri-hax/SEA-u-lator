Requirements

  • Google Chrome. Get it here: https://www.google.com/chrome/.
  • Gmail account.
  • Ollama is recommended, not required. Get it here: https://ollama.com.

Operation Modes

  • Recommended: local generation with Ollama for the most context-aware and convincing simulations.
  • Fallback: a bundled synthetic dataset is used if Ollama is unavailable.
  • The fallback dataset is lighter and usually less adaptive than live local generation, so it may be less convincing in practice.

Install SEA-u-lator

  1. Download the extension. Download
  2. Unzip the downloaded file and place the folder somewhere convenient.
  3. Open Google Chrome.
  4. Load the unpacked extension:
    1. Open chrome://extensions/.
    2. Turn on Developer mode.
    3. Click Load unpacked.
    4. Select the dist folder.
  5. Pin the extension if you want quick access to the profile popup.
  6. Optional but recommended: run Ollama locally for the best results. If not, SEA-u-lator will use the bundled dataset fallback.

Datasets

SEA-u-lator ships with two synthetic dataset files for fallback mode and research reproducibility:

  • phish_emails_cleaned.jsonl
  • phish_wrong_feedback.jsonl
  • Documentation: datasets/README.md

Dataset Risk FAQ

  • Can the authors control misuse of the dataset? No. Public release does not let the authors control or monitor all downstream uses.
  • Are the authors aware of misuse risk? Yes. The release is intentional and balances risk against transparency, reproducibility, and independent evaluation.
  • Why share the dataset anyway? Because the research artifact is stronger when fallback behavior and training materials can be inspected and reproduced.
  • What lowers the operational misuse potential? The release is limited to synthetic phishing-themed text and synthetic feedback, and the fixed fallback dataset is less adaptive than live local generation.
